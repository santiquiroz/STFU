# v1.6 Fase C — UI Voice Studio: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal:** La UI de la estación de voz — visualizador de espectro + medidor de reducción en dB, editor de cadena de plugins (auto-generado del catálogo), preset picker, A/B bypass y Music Mode. El backend (Fases A+B) ya expone todo; esto es el frontend que lo consume.

**Architecture:** React 19 + TanStack Query + Tailwind v4 (dark zinc/green). Sin router — tabs por `useState` en App. Se agrega una tab **"Estudio"** (visualizador + editor de cadena + presets); los toggles A/B y Music Mode van en la tab Control (Simple.tsx). El visualizador es canvas greenfield leyendo `status.streams.feeder.audio` del poll de 500ms existente. El editor de cadena auto-genera controles del `Parameter` metadata de `GET /plugins`. Todo reusa los primitivos de `components/ui.tsx`.

**Tech Stack:** React 19, TanStack Query 5, axios, Tailwind v4, Canvas 2D, TypeScript. Sin deps nuevas. Gate: `npm run type-check` por task + build final + smoke E2E.

**Spec:** `docs/superpowers/specs/2026-08-19-v16-voice-studio-design.md` (Fase C)

## Global Constraints

- Base: master post Fase B (merge `1505cc7`). Frontend-only (`frontend/src`). Backend no se toca.
- Correr desde `frontend/`: `npm run type-check` (tsc --noEmit) debe pasar en cada task; `npm run build` verde al final.
- Tema dark zinc/green, copy en español, primitivos de `components/ui.tsx`. Diseño INTENCIONAL (anti-template): el visualizador es la "prueba de que funciona" del research — debe verse premium (jerarquía, movimiento suave, color semántico).
- Backend ya provee: `GET /plugins`, `GET/POST/DELETE /presets`, `POST /feeder/bypass`; `status.streams[target].audio = {pre_db, post_db, reduction_db, spectrum_pre[48], spectrum_post[48]}` y `.bypass`.
- Commits en español, convencional, sin `Co-Authored-By`. No romper Control/Modelos/Sistema existentes.

### Task 4: SpectrumVisualizer + ReductionMeter (canvas)

**Files:** Create `frontend/src/components/SpectrumVisualizer.tsx`, `frontend/src/components/ReductionMeter.tsx`

**Interfaces:**
- Consumes: `usePipelineStatus()` → `status.streams.feeder?.audio`.
- `SpectrumVisualizer`: `<canvas>` + `requestAnimationFrame`. Dibuja las 48 bins log-espaciadas: barras del espectro POST (verde) con overlay del PRE (tenue/zinc) para mostrar "input vs removido". dB floor -120 → altura normalizada. Suavizado temporal (interpola entre frames para que no salte con el poll de 500ms). Responsive (max-width, resize observer o canvas fluido). Placeholder elegante cuando no hay stream activo.
- `ReductionMeter`: muestra `reduction_db` grande (el número que el research dice que impresiona: "−24 dB de ruido reducido") + una barra. Verde cuando reduce, neutral en 0/bypass. Lee `pre_db`/`post_db` para contexto.

DISEÑO (crítico — es el "proof it's working"): movimiento suave (rAF + lerp), color semántico (verde=señal limpia, zinc=ruido removido), jerarquía (el número de dB es el héroe), sin librería. Debe verse premium, no un wireframe. Grid/ejes sutiles. Respetar `prefers-reduced-motion` (sin animación si está seteado).

- [ ] Implement (canvas + rAF con cleanup en unmount). type-check + build PASS. Commit — `feat(ui): visualizador de espectro (input vs removido) y medidor de reducción en dB`

### Task 5: ChainEditor (auto-form del catálogo)

**Files:** Create `frontend/src/components/ChainEditor.tsx`, `frontend/src/components/PluginRow.tsx`

**Interfaces:**
- Consumes: `usePlugins()` (catálogo), `ParamControl` (Task 3), `startFeeder` con cadena (Task 1), `setFeederParameter`.
- `ChainEditor`: gestiona la cadena actual `PluginConfig[]` (estado local). Lista ordenada de `PluginRow` (cada uno = un plugin con sus `ParamControl` auto-generados del catálogo). Agregar plugin (dropdown del catálogo), quitar, reordenar (subir/bajar). "Aplicar" reinicia el feeder con la cadena (`startFeeder(input, chain)`) — con nota de que reordenar/agregar reinicia el stream (el swap live de add/remove es futuro). Cambiar un param de un plugin ya activo usa `setFeederParameter(index, id, value)` en vivo (sin restart).
- `PluginRow`: nombre del plugin + sus `ParamControl` + botones quitar/subir/bajar.

DISEÑO: cada plugin una Card con jerarquía (nombre + controles), estados hover/focus, el orden visible (la cadena fluye de arriba a abajo = orden de proceso). Anti-template.
